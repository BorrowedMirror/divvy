# Game data sources

Research for `cargo xtask data refresh` (workstream C). Checked live on 2026-11-05
(PoE2 0.5.5.5) with UA `kalandra-data-refresh/0.1 (+https://github.com/nightah/kalandra)`.

## Summary

| Asset | Primary source | Enrichment | Records (0.5.5.5) |
| --- | --- | --- | --- |
| `stats.json.zst` | trade2 `data/stats` | aliases generated locally | 8232 |
| `bases.json.zst` | trade2 `data/items` (non-unique) | RePoE `base_items` + `item_classes` | 3129 |
| `uniques.json.zst` | trade2 `data/items` (unique flag) | - | 765 |
| `statics.json.zst` | trade2 `data/static` | - | 771 |

The trade site is authoritative for anything we send back to it (stat ids, category ids,
exchange ids), so it is always the primary source. Exports are only used to fill fields the
trade API does not expose.

## GGG trade2 data endpoints

Base: `https://www.pathofexile.com/api/trade2/data/`. No auth, plain JSON, envelope
`{"result": [group, ...]}`. Responses carry `cache-control: public, max-age=14400` and
`last-modified`; no `x-rate-limit-*` headers were returned on these endpoints, but we still
pause 1.5 s between requests and only fetch on explicit refresh.

### `stats` (~850 KB)
Groups: `pseudo`, `explicit`, `implicit`, `fractured`, `crafted`, `enchant`, `rune`
(label "Augment", entry `type` is `augment`), `desecrated`, `sanctum`, `skill`.
Entry: `{id, text, type}` e.g. `{"id":"explicit.stat_3299347043","text":"# to maximum Life","type":"explicit"}`.
Notes:
- Explicit templates generally omit the leading `+` (`# to maximum Life`), pseudo keep it
  (`+#% total to Cold Resistance`). Items in game print `+45 to maximum Life`.
- Some texts contain `\n` (multi-line mods).
- ~80 duplicate `(group, id)` pairs and ~40 duplicate `(group, text)` pairs (different
  ids, same template: genuinely ambiguous, left for the matcher to resolve).
- No `option` stats were present in PoE2 data at the time of writing.
- No dedicated group for sanctified mods; `kalandra-data` searches them as explicits.

`StatDef.kind` = group id. Aliases generated by `xtask/src/data/normalise.rs::stat_aliases`:
- sign variants: `# X` gains `+# X` and `-# X` (negate); `+# X` gains `# X` and `-# X` (negate);
- `#% increased` <-> `#% reduced`, `#% more` <-> `#% less` (negate);
- an alias equal to a real template of the same kind is dropped (avoids false ambiguity).

### `items` (~190 KB)
Groups: `accessory`, `armour`, `currency`, `flask`, `gem`, `jewel`, `map`, `weapon`,
`sanctum`, `wombgift`. Entries are either a base `{type}` or a unique
`{type, text, name, flags: {unique: true}}`; legacy uniques carry `disc: "legacy"`.
The trade API does **not** give the sub-category (`armour.helmet`) or the in-game item
class of a base, hence the RePoE enrichment. Uniques with `disc` are skipped.

### `static` (~185 KB)
Exchange items by group (`Currency`, `Fragments`, `Runes`, `Essences`, `Waystones`, ...).
Entry `{id, text, image}`; `image` is a path relative to `https://web.poecdn.com`
(we store it absolute). `{"id":"sep"}` entries are UI separators and are skipped.

### `filters` (~10 KB)
Search filter definitions. Not bundled; used as the reference list of trade category ids
(`type_filters.category`: `weapon.onesword`, `armour.helmet`, `accessory.ring`,
`flask.charm`, `map.waystone`, `currency.omen`, ...) for `normalise::trade_category`.
Workstream B consumes it at runtime via `TradeClient::data`.

the public endpoints with a descriptive User-Agent and respect for rate limits
(https://www.pathofexile.com/developer/docs). We redistribute only the derived text needed
to build trade queries, with attribution in the manifest `sources`.

## RePoE fork (PoE2 exports)

`https://repoe-fork.github.io/poe2/` (GitHub Pages of `repoe-fork/poe2`, generated by
`repoe-fork/repoe-fork` from the game's `.datc64` files). The index page title carries the
game version (`RePoE - PoE2 version 0.5.5.5`), which we record as `game_version`.

Used:
- `base_items.min.json` (~3.1 MB, 5496 entries, keyed by metadata path): `name`,
  `item_class` (id like `Helmet`, `Body Armour`, `UtilityFlask`), `release_state`,
  implicits, properties, tags, drop level.
- `item_classes.min.json` (~9 KB): class id -> display `name` (`Helmets`, `Charms`,
  `Quarterstaves`) which matches the `Item Class:` header of copied items.

Available but not used yet: `uniques.min.json` (449 entries; name + item class, no base
type), `mods.json`, `mods_by_base.json`, `stat_translations/` (would allow
richer alias generation and tier data later), `skill_gems.json`.

Coverage check: every trade2 base except `Timeless Jewel` exists in RePoE base_items.
Non-matching bases fall back to the trade group id / label.

Licensing: RePoE code is MIT (c) 2016 brather1ng; its LICENSE states that the generated
data files are owned by Grinding Gear Games and must be used in accordance with their
terms. Same footing as the trade data.

## poe2db.tw

Community wiki-style database (bases, uniques, mods, patch diffs). No documented API or
data license; scraping HTML would be brittle and unlicensed. Useful for manual
verification only; **not** used by the pipeline.

## Pipeline

`cargo xtask data refresh [--offline]`:
1. Download the sources above into `target/data-cache/` (or reuse them with `--offline`).
2. Normalise (`xtask/src/data/normalise.rs`, pure + unit-tested), sort deterministically.
3. Write `crates/data/assets/{stats,bases,uniques,statics}.json.zst` (zstd 19) and
   `manifest.json` (schema version, generated_at, game version, per-file sources, sha256
   of the decompressed JSON, record counts) via `kalandra_data::write_dir`, then reload
   them with `kalandra_data::load_dir` as a sanity check.
4. Run the parser corpus (`cargo nextest run -p kalandra-core`); a failure is reported as
   a warning (expected while the parser is being implemented).

Total compressed assets: ~150 KB.
